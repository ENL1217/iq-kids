## ✨ What Makes This Different

- **Six question types** × **three difficulties**: matrix, sequence, spatial, number series, analogy, multi-attribute
- **Not just "is it right?" — "why?"**: every wrong answer comes with a guiding question (not the answer), then a full explanation. Kids learn the *reasoning process*, not just the answer
- **Personal skill radar**: see which of the six topics you're strong in, which need practice. Data stays in your browser
- **Learn mode / Test mode**: practice with hints, or take a timed challenge with no hints until the end
- **Completely free, open, ad-free, no data collection**

## 👨‍👩‍👧 For Parents & Teachers

### How to use
1. Open the link above — no registration, no install needed
2. From the main menu, pick a topic card (e.g. Matrix Reasoning)
3. Pick a difficulty: ⭐ Easy / ⭐⭐ Mid / ⭐⭐⭐ Hard
4. After a round, see the skill radar and a list of any wrong answers to review

### Age guidance
- **Grades 1–2 (ages 6–8)**: start with Easy, kids may need an adult alongside
- **Grades 3–4 (ages 9–10)**: Mid is the sweet spot; Hard with help
- **Grades 5–6 (ages 11–12)**: ready for any difficulty
- **Older / advanced learners**: Hard is genuine thinking practice

### Privacy
- ✅ **No personal data collected** — no names, emails, photos
- ✅ **All data lives in your browser only** — clearing browser data wipes it (a feature, not a bug — least-privilege for children's data)
- ✅ **No backend server** — pure static site
- ✅ **No third-party tracking** — no Google Analytics, no ad SDKs

### Feedback
Each question card has a **"💬 Feedback this question"** button at the bottom-right. If a question feels too hard, the answer looks wrong, or the visual broke — please tap it and tell us. Your feedback goes directly to a Google Sheet the maintainer reads.

There's also a **"💬 Got thoughts about the site?"** button on the main menu for general feedback (feature requests, bugs, etc.).

### Architecture in one minute
- Pure HTML/CSS/JS, **no framework**, no build step (just static files)
- ES modules under `web/js/`
- Questions are **standalone JSON files** in `questions/<topic>/<difficulty>/*.json`
- A frontend renderer (`web/js/renderer.js`) dispatches by `visual.type` to specific helpers (matrix grids, isometric cube stacks, etc.)
- All visuals **drawn with SVG** — no images, scales perfectly on any screen
- Questions generated by a Node.js generator (`tools/gen-<topic>.mjs`) so the bank can grow procedurally while maintaining structural and pedagogical quality
- Continuous integration validates every question file on every push

See [docs/architecture.md](docs/architecture.md) for the full design decisions.
